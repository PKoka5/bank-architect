## Equipment corrections

- Primary tables now include 647 Melee, 430 Ranged and 443 Magic exact identities.
  The 23 Melee additions cover normal-world g/t full helms, released Dragon and
  Neitiznot cosmetics, ornamented books and usable Void melee ornaments.
  Ranged adds both DHCB colours and Dragon crossbow (cr); Magic adds ward (or).
  The latter belongs to fortified ward (f), not the unfortified base ward.
- The source review TSVs and explicit development compilers reproduce all three
  artifacts. Generation/check modes remain development-only. No identity is
  expanded by name at runtime and no new automatic Alch candidate is added.
- A corpus test finds standard cosmetic suffix counterparts of reviewed bases
  in the compiled registry. Every such item must be included with the reviewed
  equivalent policy or explicitly excluded. Eight proposed/unreleased PvP Arena
  ornaments remain excluded. The ward's fortified counterpart is explicit.
- Only known usable two-handed weapon facts suppress primary offhands. Unknown
  handedness no longer implies two-handed. Tests retain an unknown weapon's
  offhand and still exclude it for the real known two-handed Tbow identity 20997.
- Without stats, an exclusively reviewed Ranged/Magic accessory no longer gets
  consumed by the Melee fallback. Real Melee-capable and reviewed shared items
  retain their existing eligibility.
- Owned family coherence precedes Melee's stable item-ID tie-break. Stronger
  actual gear still wins. Fourteen g/t metal armour families have exact head,
  body, legs, skirt and shield order. Independent catalog-name checks preserve
  the original 77-family fingerprint separately from the added families.

`EquipmentVariantRegressionTest` reproduces the trimmed Rune/Adamant choice,
both coloured DHCBs, decorated fortified ward, missing stats, placeholders,

## Profile settings

The active profile's options now synchronize the global keys displayed by
RuneLite, at startup, profile/preset switches, option saves and settings refresh.
Only changed values are written. Matching internal config events are ignored by
this plugin; other subscribers still receive the events. Unrelated events are
not discarded. Scoped profile preferences remain the source of truth.

`ProfileOptionsSynchronizationTest` dispatches synchronous ConfigChanged events
through the real plugin handler, checking Fixed/Flexible A/B profiles, subsequent
global edits, independent built-in modes, Frequently Used and no unwanted Custom.
The cached official RuneLite 1.13.4 ConfigManager source confirms unchanged values
emit no event and changed values post synchronously after invalidating the config
proxy. Existing lifecycle tests cover stale actions and profile isolation.

## Snapshot compatibility and recovery

A literal `BAkeep1`/rules-7 fixture represents the 0.9.9 serializer and is not
regenerated by the test. It must remain readable and retain destinations/order
while new entries append. Current rule descriptions advance to rules 8; old
accepted targets remain usable and are not silently replaced.

Tab Layout offers **Forget kept blueprint** only when the active profile has a
snapshot. Confirmation clears just that snapshot. The action requires matching
profile/editing context and exact stored value, runs on the client thread and
returns its result on Swing. A fresh bank or successful analysis is not required,
so unsupported/damaged records have a recovery path. Nothing is automatically
discarded. Personal tab layout, saved item orders, corrections and references
remain unchanged. Future data still cannot be overwritten by normal acceptance.

Lifecycle cases cover valid/corrupt/future records, a closed bank and failed
analysis, exact write scope, changed snapshots, settings and switched profiles.
The panel test checks that recovery stays reachable without a valid preview.
An image is rendered to `build/reports/blueprint-recovery/failed-analysis-225.png`.
